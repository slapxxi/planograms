# AGENTS

## Commands

- `npm run build` — typecheck (`tsc -b`) + Vite build; тестов в репозитории нет.
- Проверка перед завершением: `npm run build && npm run lint && npm run format:check`.
- `npm run dev` поднимает пользователь локально; агент не запускает сервер сам.
- Push в `main` триггерит `.github/workflows/deploy.yml` (GitHub Pages). Локальные изменения не видны на сайте до push.

## Structure

- Алиас `~` = `src` (настроен в `vite.config.ts` и `tsconfig.app.json`); компоненты импортируются как `~/components/...`.
- Каждый компонент лежит в отдельном файле `src/components`. Хелперы/константы, нужные только одному компоненту, остаются в нём; общие — в `~/lib/...`.
- Компоненты объявлять как `let ComponentName = (props: Props) => { ... }`, без `function ComponentName`; `export default ComponentName` в конце файла.
- Не деструктурировать props в сигнатуре: `let Component = (props: Props) => { const { ... } = props; ... }`, деструктуризация — первая строка тела.
- Вместо «сырых» `useEffect` в компонентах использовать специализированные хуки по назначению; один доменный хук предпочтительнее набора `useState`/`useEffect`/`useRef` в компоненте. Для обратных вызовов внутри эффектов — `useEffectEvent`. Хуки для одного компонента лежат в одноимённом `Component.hooks.ts` (`src/App.hooks.ts` для `App`), общие — в `src/hooks/`.

## Data model

- Источник истины — `src/data/planograms.ts`: `groups → shelves → products`; `src/data/productImages.ts` — реестр ключей и URL изображений.
- Номера ячеек вычисляются `numberProducts()` сквозь все группы (пустые полки пропускаются): не хардкодить номера, считать этим порядком.
- `faces` — сколько фото рисовать в режиме «Фейсы»; `faceSpan` — ширина ячейки в фейсах (по умолчанию = `faces`); `height` — сколько раз повторить фото по высоте в режиме «Фейсы» (по умолчанию 1, хелпер `productHeight()`); если в `name` несколько наименований через `/` и `height > 1`, изображения чередуются по кругу вместо повтора первого. Бейдж: `номер/span · см`; 1 фейс = 8 см (`CM_PER_FACE` и хелперы в `planograms.ts`).
- Полки — flex-ряды (`src/components/ShelfRow.tsx`), ширины считаются в `~/lib/planogram.ts`: условная колонка = 1 см (`unitWidth(cellSize)` из `FACE_WIDTH_BY_SIZE`: `3xs=28`, `2xs=36`, `xs=44`, `sm=56`, `md=68`, `lg=84` px; `CELL_GAP=2`, `CM_PER_FACE=8`), ячейка = `faceSpan * CM_PER_FACE` колонок, отступы `SHELF_PADDING_X=2px` с каждой стороны. Переключатель размера в шапке меняет только ширину; `md` — текущий размер по умолчанию. Чтобы заполнить полку до конца, выравнивать суммарный `faceSpan` по первой полке группы; флаг `fill` был явно отклонён.
- Режим «Фейсы» берёт только первое фото товара; исключение: ячейки с несколькими наименованиями через `/` и `height > 1` чередуют изображения по кругу. Тултип показывает все. Новый ключ добавлять сразу в `ProductImageKey` и `productImages`, `src: import.meta.env.BASE_URL + 'products/...'`.
- Группы `tvorog`, `yogurt`, `health`, `baby` — пустые плейсхолдеры.

## Product photo workflow

- Новые фото кладутся в `public/products/incoming/`: убрать фон/обрезать по субъекту, WebP RGBA высотой ~400px, переименовать в kebab-case в `public/products/`, исходник удалить из `incoming`, затем зарегистрировать ключ и ячейку. Исключение: `milkFilmAssorted` — только ресайз без rembg; следовать явной инструкции пользователя.
- Если изображение в `incoming` уже с вырезанным фоном, не запускать `rembg`: только обрезать по субъекту, сохранить WebP RGBA высотой ~400px и зарегистрировать ключ/ячейку.
- Отдельного скрипта обработки в репозитории нет (временный helper и `rembg` в окружении отсутствуют) — при необходимости воссоздать инструмент.
- Два фото на ячейку: первый файл → первый бренд в названии; «свапни изображения» меняет порядок.
- Пользователь диктует по одной ячейке: «след. Название - faces [- height]», «N/span», «Nсм», «след ряд», «такое же содержимое как ячейка N». Высота — последний параметр через `-`, по умолчанию 1. Не выдумывать товары и не пытаться читать фото: в этой среде нет ввода изображений.

## UI conventions

- Интерфейс на русском; Prettier: `singleQuote`, без точок с запятой; радиус 2px (`rounded-[2px]`).
- Тема: `src/theme.ts`, CSS-переменные в `index.css` (`:root` и `.dark`), стартовый скрипт в `index.html`; ключ `planogram-theme` в localStorage должен совпадать во всех трёх местах.
- Драг-скролл на десктопе только мышью (`DragScrollArea`): начинается сразу при `pointerdown`, скролл батчится через `requestAnimationFrame`, лишние React-рендеры во время drag не допускаются; тач остаётся нативным; изображения всегда `draggable={false}`.
- Тултипы позиционируются по `window.visualViewport` и остаются в пределах видимой области при пинч-зуме на мобильных.
- Глобальный поиск (`SearchBar`, `~/lib/search.ts`): ищет только по названию товара через `numberProducts`, без номеров ячеек и категорий/групп; нечёткий поиск по токенам поддерживает префиксы и опечатки (`сав как` → `Савушкин с какао`); точные совпадения идут первыми; подсвечивает совпадения вместо фильтрации; при вводе первая релевантная ячейка сразу подсвечивается и прокручивается чуть выше центра экрана, как при наведении/выборе подсказки;
  последние выбранные запросы (до 3) показываются при фокусе всегда, в том числе при непустом вводе, наведение/клик по ним работают как по обычной подсказке;
  подсказки только при фокусе ввода; отдельная кнопка «Очистить»; поле липкое (`sticky top-0`), подсказки позиционируются поверх контента и слегка прозрачные;
  `/` — фокус, `Escape` — сброс; `Enter`/`done` в поле выбирает первый результат и переводит фокус на ячейку.
- У каждой группы есть кнопка сворачивания/разворачивания таблицы; поиск по подсказке автоматически разворачивает группу искомой ячейки. Наведение на подсказку — предпросмотр: если подсказку не выбрали, реверт происходит при расфокусе поиска; при выборе фиксируется только раскрытие выбранной группы, остальные таблицы возвращаются в состояние до подсветки.
- Правый клик по ячейке переключает ручное выделение; кнопка в шапке группы сбрасывает только ручное выделение этой группы и не трогает поиск.
- Поиск, режимы таблиц и свёрнутые таблицы сохраняются в query string: `?q=<название>&c=<number-base36>&v=<group-indices>&e=<group-indices>&m=<number-base36>` (`v`/`e`/`m` — значения через точку, индексы групп — base36 по порядку в `groups`, режим `faces` — просто presence); режим по умолчанию `cards` и развёрнутое состояние в URL не пишутся, `q`/`c`/`v`/`e` удаляются при пустом поиске/сбросе, `m` удаляется при пустом ручном выделении, остальные параметры URL сохраняются. В localStorage — `planogram-cell-size` (глобальный размер ячеек; `md` — по умолчанию, ключ удаляется) и `planogram-recent-queries` (последние выбранные запросы, до 3); чтение/запись через `~/lib/storage`. Размер ячеек меняется кнопками `3XS / 2XS / XS / SM / MD / LG` в шапке и влияет только на ширину. Отдельная кнопка «Очистить хранилище» сбрасывает эти ключи, параметры поиска/режимов/свёрнутых таблиц в URL и состояние интерфейса.
- Локальные константы и хелперы компонентов выносятся в одноимённые `Component.config.ts`: `src/App.config.ts` для `App`, `src/components/*.config.ts` для компонентов; JSX-иконки в `.config.ts` создаются через `createElement`.
